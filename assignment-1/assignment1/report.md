# 广义五子棋游戏与对抗搜索实验报告

## 摘要

本项目实现了一个带中文图形界面的广义五子棋系统。棋盘边长 `N` 不设置固定上限，并支持任意满足 `N >= 3`、`3 <= K <= N` 的连珠规则。系统包含人人、人机和机机三种模式，以及基础 Alpha-Beta、增强 Alpha-Beta 和 MCTS + UCT 三种可切换 AI。课程评测入口 `gomoku_ai.py::GomokuAI` 默认使用增强 Alpha-Beta。

实验使用固定随机种子和与课程裁判一致的墙钟看门狗，串行执行 AI 对随机对手和增强 AI 自我对战。原始结果逐局写入 JSONL，并由同一份原始数据生成汇总统计。这样既保留胜负、局长和平均思考时间，也不会隐藏超时、异常或非法着法。

## 1. 总体设计

### 1.1 模块划分

项目按“规则、决策、表现、验证”分层：

| 模块 | 职责 |
| --- | --- |
| `gomoku_game.py` | 保存棋盘、当前玩家和历史；验证落子；判断四方向 K 连、长连与和棋 |
| `gomoku_ai.py` | 统一协议、时间控制、候选生成、评估函数、Alpha-Beta 与 MCTS |
| `gui.py` / `main.py` | Tkinter 界面、模式配置、棋盘绘制、后台 AI 调用和外部 AI 加载 |
| `run_experiments.py` | 固定种子实验、裁判式超时检查、逐步计时、断点恢复与统计汇总 |
| `tests/` | 规则、协议、极短时限、大棋盘以及实验矩阵一致性测试 |

棋局引擎不依赖 GUI 或 AI。GUI 只通过棋局对象取得棋盘副本并提交落子，因此同一套规则可以服务三种对战模式和自动实验。

### 1.2 三种对战模式

1. **人人对战**：当前格为人类玩家时，鼠标点击被换算为从零开始的 `(row, col)`，通过规则层验证后落子。
2. **人机对战**：玩家可以执黑或白。AI 在守护线程中计算，主线程持续响应窗口事件，并通过结果队列接收着法。
3. **机机对战**：黑白双方可独立选择基础 Alpha-Beta、增强 Alpha-Beta、MCTS，或从文件加载符合课程协议的外部 AI。界面允许暂停和继续。

每次新对局都会递增会话编号。旧线程即使在重开后才返回，其结果也因编号不匹配而被丢弃，避免污染新棋局。GUI 还设置独立的硬截止时间；超时、异常或非法着法均按协议判负。

### 1.3 广义规则与参数化

程序只要求：

\[
N \ge 3, \qquad 3 \le K \le N.
\]

棋盘内容为 `0=空位`、`1=黑棋`、`2=白棋`。黑方先手。每次落子后从该点沿横、竖、主对角线和副对角线向两端计数；总长度不小于 `K` 即获胜，因此长连也判胜且没有禁手。棋盘填满仍无人获胜时为和棋。

规则、候选范围、终局检查、评估进度和 rollout 长度均读取构造函数中的 `N`、`K`，没有写死 15 路或五连。单元测试还覆盖了 `3x3, K=3` 和 `40x40, K=7`。

## 2. AI 算法

### 2.1 统一协议与保底着法

课程裁判只调用：

```python
GomokuAI(player_id, board_size, win_length)
get_move(board, last_opponent_move, time_limit) -> (row, col)
```

`get_move` 首先启动墙钟计时，然后在任何搜索前确定一个合法保底着法：优先中心，其次对手上一手附近，最后逐行查找空位。后续搜索即使被截止，也能返回这个坐标或最后一个完整深度的最佳坐标。传入棋盘只读；搜索在副本上进行。

在三种策略中，正式搜索前都会做两轮一手战术检查：先寻找己方立即获胜点，再寻找对方立即获胜点并阻挡。这一步降低了浅搜索和随机 rollout 漏掉直接胜负的风险。

### 2.2 基础 Alpha-Beta

基础版本使用 Negamax 形式的 MiniMax 和 Alpha-Beta 剪枝。除 `3x3` 使用深度 4 外，其余配置使用固定深度 2。候选点限制在已有棋子的一格邻域内，根节点最多保留 14 个、内部节点最多 12 个。该版本不使用迭代加深、置换表或复杂排序，作为对照组。

```text
NEGAMAX(board, depth, alpha, beta, player):
    if deadline reached: abort current search
    if depth == 0: return EVALUATE(board, player)
    best = -infinity
    for move in nearby_empty_cells(board):
        make move for player
        if move wins: score = WIN - ply
        else: score = -NEGAMAX(board, depth-1, -beta, -alpha, opponent)
        undo move
        best = max(best, score)
        alpha = max(alpha, score)
        if alpha >= beta: break
    return best
```

基础评估扫描四个方向的极大连续段。长度为 `l`、开放端数为 `o` 的非终局棋型取：

\[
V_{basic}(l,o)=(l+1)^3o.
\]

己方棋型加分、对方棋型减分；对手分数额外乘 `1.12`，使防守略优先于同等级进攻。

### 2.3 增强 Alpha-Beta

提交使用的增强版本在同一 Negamax 框架上加入：

- **迭代加深**：从深度 1 开始，只在一层完整结束后更新可返回结果；小棋盘最高深度 9，其余最高深度 7。
- **着法排序**：优先上一深度最佳着法、立即获胜、立即阻挡、局部连续潜力及靠近中心的点。
- **置换表**：使用随 `(row, col, player)` 生成的 64 位 Zobrist 异或散列，并以 `(hash, player, depth)` 为键；发生剪枝的节点不按精确值写入。
- **动态分支限制**：通常保留 18-22 个候选；深层或接近截止时间时缩减到 10 或 6 个。
- **两格邻域候选**：比基础版观察更广，但仍避免在整个空棋盘上展开。

```text
ITERATIVE-DEEPENING(board, deadline):
    fallback = first legal move
    preferred = fallback
    for depth = 1 ... maximum_depth:
        if insufficient time: break
        try:
            move = ALPHA-BETA-ROOT(board, depth, preferred)
        on deadline:
            break
        fallback = preferred = move
    return fallback
```

#### 强化评估函数

增强评估由连续段和长度为 `K` 的滑动窗口两部分组成。

对长度 `l < K`、开放端数 `o` 的连续段，基础值为：

\[
V_{run}(l,o,K)=\left\lfloor 10^{1+6l/K}\right\rfloor(2+2o).
\]

若 `l=K-1`，双开放端再乘 40，单开放端乘 12。包含己方棋子且不含对手的 K 窗口按 `5^c` 加分，其中 `c` 是窗口内己方棋数；`c=K-1` 时乘 30。对手窗口对称扣分，但 `K-1` 威胁乘 36，且连续段仍带 `1.12` 防守系数。终局值使用远大于启发值的常数，确保真实胜负压倒非终局棋型。

这些公式使用比例 `l/K` 和条件 `K-1`，因此 K 改变时，威胁等级会同步改变，而不是只识别“活四”或“五连”。滑动窗口还能识别连续段扫描不易表示的带空隙潜力。

### 2.4 MCTS 与 UCT

MCTS 节点保存局面、轮到的玩家、父子关系、访问次数、累计根玩家收益和未扩展候选。一次迭代包含：

1. **Selection**：从已完全扩展的节点按 UCT 选择子节点；对手层反转利用项。
2. **Expansion**：从一格邻域候选中扩展一个节点，小棋盘最多保留 16 个，大棋盘 12 个。
3. **Simulation**：优先立即获胜和立即阻挡，再从局部潜力较高的 6 个候选中加权随机选择。
4. **Backpropagation**：胜、负、和分别以 `1`、`-1`、`0` 从根玩家视角回传。

UCT 选择值为：

\[
UCT_i=\bar X_i + \sqrt{\frac{2\ln N}{n_i}},
\]

其中 `N` 是父节点访问次数，`n_i` 是子节点访问次数。rollout 最多执行 `max(10, 3K)` 步；若未终局，则用轻量连续段评估映射为 `0.2`、`-0.2` 或 `0`。这个上限与逐步截止检查共同防止单次模拟越过时间预算。

### 2.5 时限管理

计时从 `get_move` 入口开始，包含输入检查、保底选择和棋盘复制。内部软截止时间早于裁判硬截止。安全余量为：

\[
R=\min\left(0.4T,\ \max(0.005,\min(0.25,0.15T))\right),
\qquad D=t_0+T-R.
\]

递归入口、候选生成、排序、整盘评估、哈希计算和每个 MCTS 阶段都会检查 `D`。搜索超时通过内部 `SearchTimeout` 回退，不会泄漏到课程裁判。极短时限下若复制后已没有安全预算，则跳过搜索直接返回保底着法。

## 3. 实验方法

### 3.1 环境与可复现性

- 操作系统：Windows 11 (`10.0.26200`)
- Python：3.14.6，Anaconda 构建
- 项目依赖：Python 标准库与 Tkinter；实验不调用外部引擎或网络服务
- 执行方式：所有对局串行运行，避免并行竞争扭曲墙钟时间
- 主随机种子：`20260928`
- 计时器：`time.perf_counter()`

每局重新创建 AI。随机对手使用独立 `random.Random(seed)`；相同配置、时限和局号在三种策略间共享同一对手种子。MCTS 也由主种子派生逐局种子。每个 50 局批次中，测试对象执黑 25 局、执白 25 局。

实验看门狗与课程 `arena.py` 相同：在守护线程中调用 `get_move`，主线程只等待 `time_limit`；超时、异常、越界、非整数坐标或占用点均立即判负。任何协议失败都会保留在原始数据中，不会重跑后删除。

### 3.2 实验矩阵与指标

对随机 AI 的矩阵包含 900 局：

\[
3\text{ strategies}\times 2\text{ configurations}\times
3\text{ time limits}\times 50\text{ games}=900.
\]

增强 Alpha-Beta 自我对战包含 300 局：

\[
2\text{ configurations}\times 3\text{ time limits}\times
50\text{ games}=300.
\]

两组配置为 `(9,4)` 和 `(15,5)`，三档每步时限为 `0.5s`、`1.0s`、`5.0s`。报告统计胜/负/和、胜率、积分率（胜 1、和 0.5）、先后手结果、平均局长，以及 AI 每步墙钟时间的均值、中位数、P95 和最大值。

每组 A、B 各执黑 25 局，因此前三个小棋盘组和 15 路的 0.5/1.0 秒组中，A/B 总成绩均为 25-25；这不代表没有先手效应。`9x9, K=4` 三档时限均为黑方 50 胜，平均仅 7.00-7.12 手。`15x15, K=5` 对预算更敏感：0.5 秒时白方 50 胜且平均 12 手，1 秒时黑方 50 胜且平均 9 手，5 秒时黑方 48 胜、白方 2 胜，平均 14.16 手。高预算组出现 9、13、17、19 和 22 手等多条轨迹；截止时刻附近能否完成下一深度会使确定性搜索表现出运行时敏感性，但这些样本仍共享同一空棋盘开局，不能当作 50 个完全独立的棋力样本。

### 4.4 课程裁判合规验证

另用课程原版 `arena.py` 运行默认 `15x15, K=5, 5s, 2局` 并交换先后手。`GomokuAI` 执黑 9 手获胜、执白 10 手获胜，总比分 `2.0:0.0`；两局均以五连正常结束，没有超时、异常或非法落子。

## 5. 讨论与反思

### 5.1 候选裁剪的收益与风险

邻域候选把大棋盘上的分支数从最多 `N^2` 降到已有棋群附近，使 Python 能在时限内达到更深层次。但它属于启发式完备性取舍：某些远离现有棋群的全局布局点不会被搜索。动态候选上限也可能在多个近似强点并存时裁掉真正最优着法。

### 5.2 评估函数的局限

连续段与 K 窗口能够表达开放端、断点和 `K-1` 威胁，但各窗口之间不是独立事件，累加会重复计算交叉棋型。当前权重由直观尺度设计，而非从大规模局面学习得到；它对双威胁的表达仍是多个局部分数之和，不能完全替代更深的战术验证。防守乘数也可能让 AI 在某些可强攻局面中过度保守。

### 5.3 确定性自我对战

增强 Alpha-Beta 的候选排序和相同分数处理是确定性的。同配置、同预算、空棋盘开局会产生高度相关的棋谱；例如 `9x9, K=4` 的 1 秒和 5 秒组都固定为黑方 7 手获胜。大棋盘 5 秒组并非完全相同，因为迭代加深能否在软截止前完成下一层会受运行时抖动影响，最终出现多种局长。无论是否完全重复，这 50 局都不能解释为 50 个独立随机样本。更合理的后续实验可以使用成对的随机合法开局，或在相同评估分数间使用受控随机破同分，同时单独保留标准空棋盘结果。

### 5.4 Python 看门狗限制

课程裁判和本实验都使用守护线程实现墙钟超时。Python 无法安全强制终止一个仍在运行的线程，所以超时后只能判负并忽略该线程。自己的三种 AI 通过软截止主动返回，能避免遗留线程；对任意外部 AI，若需要真正隔离 CPU 和内存，进程级裁判会更可靠。

### 5.5 可继续改进的方向

- 使用增量棋型计数代替每个叶节点整盘扫描。
- 为置换表保存 exact/lower/upper bound 类型，允许安全复用剪枝节点。
- 增加杀手着法、历史启发和更精确的必胜威胁搜索。
- 让 MCTS 复用上一手后的子树，并研究并行 rollout。
- 使用多样化但成对一致的开局集合，减少确定性重复并更公平地比较先后手。
