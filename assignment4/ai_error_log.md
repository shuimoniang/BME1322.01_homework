# AI实际错误记录

## 排序文案的中文编码损坏

整理19条发现的排序与分配时，一次经PowerShell管道传入Python的中文文案被编码成问号。数值记录未改变，但排序理由和部分标签不可读。检查生成器和文稿时发现后，将相关文案改为明确的UTF-8源文件生成，恢复中文，并增加文稿无连续问号和替换字符的检查。报告、主要日志、补充发现及条款索引均已重新生成并检查。

## 将分类朴素参考线误接到回归评估分支

- 初稿在 `main.py` 中对 DummyClassifier 调用了 `evaluate(..., cls=False)`，因而会暂时得到R²/MAE等回归指标。这是任务类型路由错误，不能用这些数字充当分类参考线。
- 静态核查发现后，删除该错误调用；分类参考线逐折只在训练标签上确定多数类，再以常数分类分数计算accuracy、precision、recall、F1和AUC。
- 二分类多数类参考线的连续分数为常数，所以AUC必须为0.5，正类recall为0；验收会断言这些性质。
- 此错误在首轮代码检查中由AI自身发现并修正，尚未声称用户亲自发现。报告必须如实标注人工核查状态。

## 工具与结果验证

全部基线核对差值、原脚本输出、数据哈希、软件版本和逐样本折外预测均保留；另有协议单元测试。课程材料对C和均值R²的误导另在报告勘误节说明，不将材料问题冒充AI错误。


## 首轮完整实验未能保存树指标

首轮计算完成后，写results.json时报错：TypeError: Object of type int64 is not JSON serializable，定位到树的leaves指标。初稿错误地假定库返回的叶节点数一定是Python原生整数。根据异常堆栈定位后，在评估入口显式转为int，并增加树结果可序列化的回归测试；随后重新运行完整实验，以成功写入、重新读取和重建报告复验。此错误由AI排查并修正，未声称用户亲自发现。


## 回归器转分类的聚合口径不一致

初稿把岭回归全部303例折外预测计算的AUC=0.909853，与SVM逐折平均AUC作比较，口径不一致。现对各模型相同五折分别计算AUC、accuracy和F1，再取算术平均；报告第九节和analysis.md已更新，同口径数字保存在figures/discussion_evidence.json，不能把聚合变化解释为训练提升。
